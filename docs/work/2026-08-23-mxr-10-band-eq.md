# The 10-band graphic EQ — M13.6's EQ item

**Date:** 2026-08-23
**Branch:** `claude/roadmap-priorities-kok3vx` (session-designated; the house
convention would be `feat/mxr-10-band-eq` — recorded so the divergence is not
read as a slip)
**Roadmap item:** M13.6 — "Utility + modulation batch": the **MXR 10-band
graphic EQ**, called *"mandatory for metal; 10 biquads, trivial DSP"*. Named as
an open gap by the Mesa slice on its way out (§69: *"The graphic EQ is NOT part
of this amp and was not built — it is M13.6's MXR 10-band"*).

## Goal

A ten-band graphic EQ on the board, end to end on both front ends, whose band
centres, boost/cut range and **band-interaction behaviour** are measured against
the reference circuit rather than assumed from the RBJ cookbook.

## The two findings that shape this slice (both from reading the tree, before any code)

**Finding 1 — the roadmap's cost estimate is wrong, and in the same way §67's
and §69's entries were wrong about their own slices.** "10 biquads, trivial DSP"
is true about the *DSP* and false about the *slice*. **Every pedal on this board
is exactly three parameters**, and that is not a UI convention — it is the ABI:

- `web/src/rig.ts` — `PedalParams` is three named fields (`distortion` /
  `filter` / `level`), and the serializer, the migration path and the
  assistant's clamped tool surface all speak those three names.
- `web/worklet/clipper-processor.js:340-342` — the dispatch is three literal
  lines, `_set_param(handle, 0|1|2, params.distortion|filter|level)`.
- `web/src/components/Pedal.tsx:43-57` — `PedalFace.knobs` is documented
  "1..3 knobs" and each `KnobSpec.param` names one of those three slots.
- `native/src/ClipperEngine.h:202` — `Params` carries per-pedal named floats
  (three per pedal, two where the pedal has two).

A ten-band graphic EQ is **twelve** controls (ten sliders + GAIN + VOLUME on the
reference). The C ABI itself is *not* the constraint — `*_set_param(handle, int
param_id, float)` already takes any id, which is why the core side really is
cheap. Everything upstream of it is. **So this is an M/L slice whose weight is
plumbing, and the honest framing is: it is the slice that teaches this board to
hold a pedal with more than three knobs.**

**Finding 2 — "10 biquads" is probably the wrong model, and the acceptance bar
has to be able to say so.** The reference is a **gyrator** graphic EQ: ten
simulated-inductor bandpass legs summed in one op-amp's feedback loop, not ten
peaking sections in series. Two player-observable consequences fall out of that
topology and neither is reproduced by ten independent RBJ peaks:

1. **Adjacent bands interact.** Two neighbouring sliders up does not equal the
   sum of each one alone, because both legs are summed into one node.
2. **The Q is not constant.** A gyrator EQ's bandwidth narrows as boost
   increases (proportional-Q), so a small boost is broad and a full boost is a
   spike. That is most of why a graphic EQ "sounds like a graphic EQ".

Per §57's standing rule the model gets built from the netlist if one is
reachable, and every value that is not is recorded as a reconstruction.

**Finding 3, found in passing and worth the roadmap knowing: this EQ is the LAST
pedal type that fits the packed chain word.** `native/src/PluginProcessor.cpp:60-67`
packs the board into a `uint64` with `kChainField = 4` bits per slot and asserts
`kChainField * (kMaxChain + 1) <= 64`. At `PEDAL_TYPE_COUNT = 15` that is
`4 × 16 = 64` — **exactly full**. The sixteenth pedal type fires the
static_assert, exactly as the eighth fired the `uint32` one. Not this slice's
problem to fix; it is the next pedal slice's, and it should not discover it by
surprise.

## Approach

**Fidelity:** a NEW voice, so it cannot move a golden by construction. Phase A
is a **strictly bit-identical** refactor of the parameter path — that is its
acceptance bar, not a hope.

**Scope decision (owner, 2026-08-23): ONE branch, one PR, accepted as an L.**
The alternative on the table was splitting the param-shape work into its own
slice. Since both phases now land in one diff, attribution is preserved by
ORDERING instead: **Phase A is committed, measured and its bit-identity proof
recorded BEFORE a single line of Phase B is written.** If a golden or an
existing pedal's render moves after that commit, the cause is unambiguous. Do
not interleave the two phases' commits.

### Phase A — the N-parameter pedal shape (zero DSP, zero tone change)

`PedalParams` keeps its three named slots (every existing pedal, the assistant's
vocabulary and every saved rig keep working untouched) and gains an **optional
extra-parameter vector** carried alongside them, dispatched to ABI ids 3.. in
the worklet, clamped and allowlisted in `assistant/tools.ts` on the same terms
as the three named ones, and mirrored natively as named APVTS parameters. A
missing vector reads as "this pedal has three params", which is what every
existing pedal is.

### Phase B — the EQ itself

- `core/include/clipper/dsp/EqModel.h` + `core/src/dsp/EqModel.cpp`: ten band
  legs at the ISO centres (31.25 / 62.5 / 125 / 250 / 500 Hz / 1 / 2 / 4 / 8 /
  16 kHz), a summing node, GAIN and VOLUME.
- **`Biquad` is NOT widened in place.** It is shared with all three valve amp
  tone stacks and the cab IR generator, so changing its state type moves every
  amp's renders. If the 31.25 Hz band needs double state (see below), it gets it
  the way §35 gave `OnePoleSmoother` one — `BiquadT<T>`, with the `float`
  instantiation byte-for-byte the current class for all existing users.
- C ABI `eq_*`, worklet dispatch, web face + tokens + assistant coaching, native
  engine + APVTS + `PedalCard`, and **its own case in `identical_core_test`'s
  plugin driver** (the §64 standing note is that comp/gate/delay/wah/chorus are
  still missing from that driver — this slice adds its own and does not pretend
  to close the rest).
- Pedal type `eq`, **slot 14**, `PEDAL_TYPE_COUNT` → 15. Model line is a NEW
  category: `EQ Nº1`. Wordmark and accent are an owner call; `"Decade"` is the
  proposal (ten bands, decades of frequency), homage-never-replica per M6.8.1 —
  no "MXR", no "M108", no script logo.
- **Face:** a new `slider` layout (a ten-fader bank). The existing `bank` layout
  is knobs in a row and is not this.

### The mechanism S8 turns out to be a CONSEQUENCE of, not a parameter

The leg's own unloaded Q measures **66–90** across the transcribed bands. The
band Q a player hears is nowhere near that, because **the slider IS the damping
element**: the wiper's source impedance into the leg changes as the slider
moves, so the effective damping — and therefore the bandwidth — is a function of
slider position. **Proportional-Q falls out of the topology; it is not a
coefficient anyone chooses.** That is what makes S8 a real acceptance bar rather
than a target to fit: get the topology right and the ~3× narrowing appears, or
the topology is wrong.

### What is DERIVED, and what is RECONSTRUCTED — stated precisely

The reference for THIS pedal is a ten-band; the netlist in reach is a
**seven**-band from a different manufacturer. So:

- **TRANSCRIBED:** the leg topology, the design equation, the shared 330 Ω, the
  10 kΩ linear slider law, the summing stage's equal 10 k pair.
- **DERIVED:** the ten per-band `L`/`C1` pairs, from S2's equation and S9's ISO
  centres, holding S4's shared `R1` fixed — the same way a real design lays out
  a band.
- **RECONSTRUCTED, and named so nobody reads it as sourced:** the ±12 dB range
  (unconfirmed — the manual PDF is behind the egress wall), whether the ten-band
  reference also makes its top band first-order (S7 is a GE-7 fact), and the
  GAIN/VOLUME slider laws.

**§57's rule applies verbatim to that last row: do not re-tune any of it toward
a sound; find the ten-band's schematic.**

## How this will be measured

Each of these is a hard assert in `clipper_eq_tests` unless marked *reported*.

1. **Band centres.** Each slider alone at full boost must peak within a stated
   tolerance of its nominal ISO centre, read by Goertzel off a rendered sweep at
   44.1 / 48 / 96 kHz.
2. **Range.** Boost and cut at each band centre against the reference's stated
   ±12 dB, measured, with the shortfall/overshoot RECORDED not snugged.
3. **Proportional Q — the bar with teeth.** The −3 dB bandwidth of one band
   measured at +3 dB and at +12 dB of boost. A gyrator EQ narrows; ten
   independent RBJ peaks at fixed Q do not. Ratio asserted, value recorded.
4. **Band interaction — the second bar with teeth.** Two adjacent sliders up
   together, measured against the sum in dB of each one alone. Non-zero
   interaction asserted; the number recorded.
5. **The contrast that decides whether the roadmap was right.** The shipped
   model against **ten independent RBJ peaking biquads** at identical settings,
   worst band, in dB. *If that comes out under ~1 dB the roadmap's "10 biquads"
   framing was CORRECT and this plan's Finding 2 was wrong* — that gets
   reported as a refutation, not quietly dropped (§66's precedent: both halves
   of that slice were refused on measurement and shipped as refusals).
6. **Flat is unity.** All ten sliders centred, GAIN and VOLUME at unity → the
   render must be bit-identical to bypass, or the deviation stated in dB and
   attributed to a named component. The `BLEND 0` / `SENSE 0` precedent.
7. **The numerical floor — predicted, and the reason `Biquad` may need a double
   sibling.** A 31.25 Hz peaking section at 96 kHz sits at a pole radius over
   0.998, which is §56.4's exact shape: `float` direct-form state amplifies its
   own rounding and put an audible **−73 dBFS** hiss floor on the GOLD's drive
   divider in code that looked fine, invisible to every single-bin bar in that
   suite. Measured against a long-double build, against the project's own
   **−120 dBFS** gate. Whichever way it lands, it is measured, not assumed.
8. **Denormals (ADR 006).** The twenty biquad states rest at zero, so they are
   guarded (`Biquad::process` already flushes) and `maxAbsRestingState()` is
   asserted **exactly 0.0** after a silent tail.
9. **No oversampling, latency 0.** The EQ is linear time-invariant — the phaser
   precedent (§12) — so `setOversampling` is accepted and ignored, and the
   render is asserted **bit-identical at 1× / 2× / 4× / 8×** so a later slice
   cannot quietly add 72 samples of latency for nothing (§70's shape).
10. **The housekeeping row every pedal carries:** DC on signal (clean and with a
    +0.1 V input offset), ragged-block invariance, `reset()` vs a fresh model,
    one NaN in → 0 non-finite out, zipper on a slider slam, rate spread over
    44.1–96 kHz, CPU *(reported)*.
11. **Goldens: all five UNCHANGED at ±0.00, nothing blessed.** A new voice in no
    golden rig, touching no shared class, cannot need a bless. If one moves,
    something in Phase A was not bit-identical and that is the bug.

## What actually happened

**The plan's Finding 1 held and was the whole shape of the slice.** The DSP is
trivial; the three-parameter pedal ABI was the work. Phase A landed first and
alone, and its bar — bit-identity — was met by the strongest evidence available:
after a full rebuild `web/public/generated/clipper.js` came back **BYTE-IDENTICAL**
to its pre-slice state, so the compiled engine is bit-for-bit the same binary and
no DSP could have changed. The widening also came out smaller than planned: GAIN
rides slot 0 and VOLUME slot 2 (ordinary slot reuse, the phaser/wah/delay
pattern), so only the ten bands needed new ids.

**The plan's Finding 2 was half right and the measurement said which half.** The
reference IS a gyrator design with proportional Q — confirmed, and the published
figures turned out to be numeric rather than adjectival (~1 octave at +3 dB,
~1/3 at full boost). But the roadmap's "10 biquads" framing is closer to right
than the plan assumed: against ten independent RBJ peaks at matched width the
shipped model differs by only **0.909 dB** worst-case, and band interaction
measures **+0.004 dB** against a published "significant". Reported both ways
rather than dropped.

**The research channel was much better than budgeted for.** The plan expected
§64's outcome (nothing reachable). `WebFetch` is indeed egress-blocked on every
host including the manufacturer's own manual PDF — but github.com is reachable
and `Cushychicken/ltspice-guitar-pedals` carries a complete annotated 7-band
Boss GE-7. Nine sourced facts, six netlist-grade.

**One structural error, caught by measuring.** The first draft ran the band leg
from the pot wiper to GROUND. That puts ten pots end-to-end across the summing
node's feedback: −20 dB of flat insertion loss and essentially no equalisation.
The leg runs to the VIRTUAL GROUND, which is what makes flat-at-centre exact.

**Three measurement bugs, all mine, all in the test.** A 64-cycle window at
16 kHz is 192 samples and under-reads a high-Q leg by 3.5 dB — the top band
looked broken, and a prewarp fix plus a four-rate sweep were done before the
probe was suspected. (The rate sweep is what exposed it: the shortfall was
rate-INDEPENDENT, which a discretization error cannot be.) `reset()` was compared
against a model still ramping its smoothers. And a 20-second silent tail fails an
`== 0.0` bar while the model works correctly — the 31.25 Hz leg needs 60 s.

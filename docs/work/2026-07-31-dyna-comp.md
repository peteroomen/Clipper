# Dyna Comp / Ross-style OTA compressor — the first DYNAMICS pedal

**Date:** 2026-07-31
**Branch:** claude/dyna-comp-6f557i
**Roadmap item:** M13.1 — dynamics family, pedal `comp`. M13.3 (optical/LA-2A) and
M13.6 (noise gate) are LATER slices that reuse this slice's engine and detector.

## Goal

A player can add a `comp` pedal — an MXR Dyna Comp / Ross-style **CA3080 OTA
compressor** with two knobs (SUSTAIN + LEVEL) — on the web board and in the
plugin, and it behaves like the real box: fast attack, ~1 s release, very high
ratio, squashed pick attack, thinned low end, and a lot of gain (and therefore
noise) at the top of the SUSTAIN knob. Built as a **config-parameterized engine**
from the first line, so M13.3's optical voice is a config + one gain-cell case.

## Approach

**Deliberate tone addition** (a new pedal — there is nothing to be neutral
against). Judged against the circuit, not taste: every constant is a component
value off the schematic, and the three things the brief names as
must-model-not-approximate are modelled as circuit:

1. **The CA3080 gain cell.** `Iout = Iabc · tanh(Vd / (2·Vt))`, `gm = Iabc/(2Vt)`
   — the bipolar differential-pair law, not a `gain = f(env)` curve. `Iabc` is a
   real current computed from the sidechain's node voltages.
2. **The detector time constants.** Derived from C7/C8 10 nF + R16/R17 1 MΩ (the
   clamp), the Q3/Q4 base drive, and C9 10 µF + R18 150 kΩ (the envelope). No
   attack/release knob exists because those parts are fixed.
3. **Feed-forward vs feed-back.** Settled from the netlist, not prose: the
   detector taps the **output** of the gain cell (Q2's phase-splitter legs), so
   the Dyna Comp is **FEED-BACK**. Exposed as a measurement hook
   (`setDetectorTap`) so the claim is perturbation-testable rather than asserted.

**Engine split (the M13.3 seam), named up front.** `CompressorEngine` +
`CompressorConfig` own: input coupling, the gain-cell drive network, the gain
cell, the cell's load pole, the phase splitter, the sidechain (rectifier +
envelope), the control-current mapping, output coupling and LEVEL.
`CompModel` is a thin wrapper holding the Dyna Comp config — exactly the
`OverdriveEngine`/`SdModel`/`TsModel` precedent (docs §21). M13.3 adds a
`GainCellKind` case (LDR resistance law + its own lag) and a second config; it
must not need to touch the detector or the plumbing.

**Cross-slice:** the parallel wah slice is also building an envelope follower.
No code is shared across in-flight branches; unification is a named follow-up.
This detector is also M13.6's (noise gate) — written so that a gate is a
different mapping of the same `vEnv_`, and named as such.

## How this will be measured

`clipper_comp_tests` — player-observable, no identities:

- **Static compression curve**: dB in → dB out over a 40 dB input sweep; report
  the measured ratio above the knee and the knee position.
- **Attack** and **release** from a step, in ms/s, against the published ~5 ms /
  ~1 s and the derived `R18·C9 = 1.5 s`.
- **Sustain extension**: time for a decaying pluck to fall below a fixed
  threshold, compressed vs bypassed. This is the reason the pedal exists.
- **Attack-transient loss**, in dB (report, do not fix).
- **Noise floor / idle gain** at max SUSTAIN (report, do not fix).
- **DC offset ON SIGNAL** (shared `DcOffset.h` bars), `reset()` clean, no zipper.
- Aliasing floor at the shipped 4×.

Goldens: `./build/clipper_player_expectations_tests --golden-report` — all five
must read UNCHANGED. **No golden is ever written by this slice.**

## What actually happened

See docs §59. Summary of the decisions that were NOT on this plan:

1. The proxy blocks **every** host except github.com, so the DAFx-11 paper,
   ElectroSmash, the CA3080 datasheet PDF and coda-effects were all unreachable.
   The primary source became a GitHub-hosted **LTspice schematic of the whole
   pedal**, from which the netlist was reconstructed node by node.
2. Reconstructing it produced a finding no prose source states: the CA3080's
   **differential drive is only ~12 % of the signal**, set by the 2 kΩ offset
   trimmer against the non-inverting input's 15 kΩ AC termination — and that
   network is second order and rises with frequency, while the OTA's 150 kΩ ∥
   1 nF load pole falls. They **cancel to within 1.74 dB across 110 Hz-5 kHz**.
3. `kVbias` was cross-checked, not assumed: R1 56 k / R2 27 k off 9 V gives
   2.928 V, and the schematic's own net is named `V3P0`.
4. Q3/Q4's beta is the thing that sets the attack, so the **Gummel-Poon ISE/NE
   low-current term is modelled** rather than a flat βF — the ON Semi 2N3904 card
   then produces hFE ≈ 106 at 0.2 mA (the datasheet's own figure) with nothing
   fitted.

**The independent cross-check that validates the whole loop:** an outside LTspice
simulation reports 192 µA idle / ~16 µA settled for a 100 mV 1 kHz sine at a
37 kΩ control resistance; this model measures **199.85 µA / 16.54 µA**.

**Honesty gate — one result contradicted the plan and was reported, not fitted.**
The web spec's "SUSTAIN is not a threshold" lift measures **9.82 dB** through the
worklet, not the core's ~15.8 dB, because the rig's OUTPUT LIMITER is in that
path and takes back some of the lift on the quiet note (which at SUSTAIN 1.0 is
pushed near full scale). The bar was set from the measurement (6 dB) with the
reason written into the test, and the number is printed by the spec on every run.

**And a bug this slice made and caught:** the first implementation put the
collector current in the clamp node's KCL. Only base current flows into that
node. It starved the discharge ~β-fold — attack 500–650 ms, ratio 9:1 — while the
IDLE current still agreed with the reference simulation to 4 %. Only the settled
current under signal exposed it. See §59.8.

# CE-1 Chorus Ensemble — the JC-120's chorus in a box (M13.7)

**Date:** 2026-08-01

## Goal

A Boss CE-1 Chorus Ensemble ships as pedal type `chorus`, web and native, giving
the board a **standalone** chorus (and the CE-1's vibrato mode) instead of chorus
existing only inside the Clean 120 amp.

## Slot (RESERVED — do not choose your own)

`PEDAL_CHORUS = 10` · `skin::AccentId::Chorus` · `--accent-chorus` (magenta) ·
web type string **`'chorus'`**. Allocated in `chore/reserve-pedal-slots`;
`PEDAL_TYPE_COUNT` is already 11. **Do not renumber anything or touch the delay's
(8) or gate's (9) slots** — parallel slices own those.

## Approach

**The single most important fact about this pedal, and why it is cheap:** the CE-1
**is** the Roland JC-120's chorus circuit put in a standalone box — that is its
literal design origin (Boss's first pedal, 1976, derived from the JC-120 the year
after). This project **already models the JC-120 chorus** (`ChorusModel`, docs §5 /
§20 era, validated). So this is a **re-voicing of validated machinery**, not a new
model.

**Start by reading `ChorusModel` and measuring what it already does.** Then
research the CE-1's differences and apply only those. Research → docs §62, with
sources and gaps.

The differences to establish by research, not assumption:

1. **The CE-1 has two modes: CHORUS and VIBRATO.** Vibrato is the wet path alone
   (no dry sum) with a deeper/faster LFO; chorus is dry+wet. The amp's chorus may
   or may not already expose an equivalent — check, and reuse if so.
2. **The CE-1's LFO rate/depth ranges** differ from the JC-120's fixed voicing, and
   the pedal exposes them (the JC-120 has a rate knob and an intensity behaviour).
   Find the real ranges.
3. **The CE-1 is mono-in / stereo-out** in its original form, and there is a real
   question of what the *mono* sum sounds like. This project's board is mono
   through the pedal chain (the amp goes stereo later) — **state clearly what you
   ship and what is lost**, rather than silently summing.
4. It is a **BBD** circuit, so the same darkening/companding character questions as
   any bucket-brigade apply. `ChorusModel` already made choices here — say what
   they are and whether they match the CE-1.

**If the honest answer is "this is the JC-120 chorus with different knob ranges",
say so and ship it as that.** A re-voicing that is measured and documented is a
perfectly good slice; inventing differences to make it feel like more work is not.

**Knobs:** three slots. Likely RATE / DEPTH (or INTENSITY) / MODE. Note the
precedent: §58's wah made MODE a *continuous* SENSE control rather than hiding a
discrete switch in a float slot, and asserted that SENSE 0 was bit-identical to a
build without the feature. If MODE here is genuinely discrete (chorus vs vibrato),
that is fine — but make the mapping explicit and test both ends.

## How this will be measured

- **LFO rate vs knob**, in Hz, across the travel — a table against the researched
  range. The rate must be monotone.
- **Modulation depth** as measured *pitch deviation* in cents (a delay-line chorus
  detunes; that is the effect). Report cents at min/mid/max DEPTH.
- **Chorus vs vibrato**: in vibrato mode the dry path must be **absent** — measure
  it (the null test: a steady tone should show full pitch modulation, not a comb).
  In chorus mode the comb must be present. Two different, measurable states.
- **Comb spacing** in chorus mode vs the delay range — the notches must move with
  the LFO.
- **Against the amp's existing chorus**: measure both and state the difference in
  numbers. If they are the same machinery, the numbers should show *where* the CE-1
  differs (rate range, depth, mode).
- DC on signal, `reset()` clean, no zipper on a RATE sweep, block-size invariance.
- `--golden-report`: **all five UNCHANGED** — note `clean120_chorus` is one of the
  five and this slice must NOT disturb the amp's chorus. If it moves, that is a
  scope failure to report, not a bless candidate.

## What actually happened

**The honest answer really is "the JC-120 chorus with different knob ranges", plus
two more sourced differences — and it shipped as that.** `Ce1Model` OWNS a
`ChorusModel`; the delay line, the Lagrange interpolator, the LFO accumulator and
the ~8 ms smoothing are the amp's validated code, untouched. `ChorusModel` gained
an additive **voicing seam** (`setBaseDelayMs` / `setSweepMs` / `setRateHz` /
`setWaveform`) whose defaults are the JC values, so the amp is bit-identical by
construction. Full write-up: docs **§62**.

**Research (§62.2).** `WebFetch` 403'd on every host tried, and there is no CE-1
schematic or LTspice model on GitHub — so the channel was search-result extracts
only, like §57's first Orange release. **No schematic was ever read**, and that is
recorded rather than glossed. What WAS sourced, from multiple agreeing extracts:
the JC-120 origin, the MN3002 BBD, chorus rate **1.0–3.0 Hz** with a **~1.75 Hz
midpoint**, vibrato rate **3.2–11.6 Hz**, the delay window **3–5 / 3–7 ms**,
**triangle in chorus / sine in vibrato**, the ganged INTENSITY knob, and — the
finding that shaped the slice — that the CE-1 has a **factory MONO output jack
that mixes wet and dry**.

**The rate taper is DERIVED, and a linear pot is refuted.** The published
midpoint picks the law: log gives 1.7321 Hz (**1.03 %** off), linear gives 2.0
(**14.29 %** off). Nothing fitted.

**Mono turned out to be the point, not the compromise.** The plan asked what is
lost by summing. The answer is that summing is what the real pedal's mono jack
does — and it is exactly what makes this pedal different from the amp's chorus,
which is a *split* whose L channel is the bit-exact dry signal. A mono host taking
the amp's chorus gets **0.00 dB** of envelope movement; the CE-1 gives **14.72 dB**
of comb. What IS lost is the stereo image, and that is stated in §62.5.

**Three things went wrong and were fixed rather than bounded.**
1. Switching the LFO waveform mid-cycle **steps the delay** by 0.207·A (~14
   samples) — sine and triangle agree only at their zero crossings. Now a smoothed
   blend with a `blend <= 0` fast path that keeps the amp bit-identical.
2. Forwarding the mode to `ChorusModel` **clicked at 17.02×** the signal's own
   slew, because its mode is a hard switch and L flips meaning from dry to wet
   while the dry weight is mid-ramp. Fixed by never switching it: the owned model
   stays in `MODE_CHORUS` and vibrato is the same pair with dry at zero. **0.95×**.
3. **A pre-existing native bug**, found while extending `kFaces`: Squash sat at
   index 6 and Weeper at index 7 while `PEDAL_WAH = 6` / `PEDAL_COMP = 7`, so a
   wah card drew the compressor's face and vice versa. Corrected into enum order
   and reported loudly (§62.11). Indices 8/9 left as explicit empty faces for the
   delay and gate slices.

**Two test-premise corrections** (mine, not the model's): a freshly prepared model
still RAMPS its knobs, so it is not the right reference for `reset()` — both sides
are reset instead; and a silent buffer legitimately carries the delay ring-down at
its front, so only its tail can be asserted silent.

## Deferred to next session

- **An ADR number is needed** for §62.6 (un-ganging the CE-1's INTENSITY knob so
  no slot is dead in chorus mode). Numbers are assigned centrally, so one is
  requested rather than picked. The decision, its cost and its reasoning are
  written out in §62.6 and in `Ce1Model.h`.
- **The BBD character is not modelled** (§62.7) — no compander, no anti-alias or
  reconstruction filter, so the sources' "dark, full, throaty" is not reproduced.
  It needs a schematic, not a filter chosen by ear. Largest known gap on this voice.
- **The stereo output** — a real CE-1 into two amps is wide and this cannot be.
  Would need the pedal chain to go stereo, which is a much larger slice.
- **The vibrato-mode rate midpoint** was never published; that taper is carried
  over from the chorus law rather than derived. One line to fix if it turns up.
- **The chorus-mode delay excursion** is not separately sourced (the real panel has
  no depth knob there); the vibrato window is used for both.
- Not done, and out of scope: adding the pedal to the `nan_guard` / `denormal` /
  `param_smoothing` suites' unit lists. `clipper_ce1_tests` covers all three
  properties directly (NaN guard, exact-zero resting state, zipper), so this is
  tidiness rather than coverage.

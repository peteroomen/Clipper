# CI pipeline

**Date:** 2026-07-25
**Branch:** chore/ci
**Roadmap item:** 2026-07-24 audit — "Test & process integrity": *"There is no CI. Every suite that exists is good and passes — nothing runs them automatically."*

## Goal

Every PR to `main` and every push to `main` automatically runs the suites that already exist, so a regression is caught by the repo rather than by remembering to run four commands.

## Approach

Four required jobs plus one advisory, mirroring riff's `ci.yml` shape (name, `on:` PR-to-main + push-to-main, `concurrency` with `cancel-in-progress`).

- **core** — `cmake -S core -B build && ctest`. The 16 plain-assert targets. `build/_deps` is cached on the hash of `core/CMakeLists.txt`, which contains the pinned `chowdsp_wdf` SHA.
- **web** — `npm ci`, artifact presence check, `npx playwright install --with-deps chromium`, `npm run build` (tsc --noEmit && vite build) as its own step so a type error is attributed correctly, then `npx playwright test`. Report uploaded on failure.
- **node-suites** — `test:server`, `test:history`, and the Electron shell tests.
- **commit-messages** — Conventional Commits gate over the PR's first-parent range.
- **native** *(advisory)* — JUCE build + `clipper_identical_core` / `clipper_chain_edit`.

Two decisions worth recording:

**The Electron job deliberately skips `npm ci`.** `electron/serve.mjs` and `config.mjs` import nothing from `electron`, and their tests import only `node:` builtins plus those two modules — verified locally: 16/16 pass with no `node_modules` present. Installing `electron` as a devDependency would pull ~100 MB per run for no coverage.

**The commit gate is a regex, not commitlint.** riff enforces Conventional Commits with commitlint + husky, but this project's root `package.json` is deliberately dependency-free (the whole assistant proxy is zero-dependency by design), and adding a devDependency tree at the root to lint commit *subjects* is a poor trade. A dependency-free regex enforces the same rule. It skips merge commits and reads only first-parent subjects, so a merge does not re-validate history that already passed on its own PR. Note the existing 101 commits use `Docs:` / `Native:` / `WASM:` prefixes and would NOT pass — that is fine, the gate only sees the PR's own range.

**`native` is advisory (`continue-on-error: true`) for now.** The Linux JUCE system-dependency list is easy to get subtly wrong, and a new job that flakes must not block PRs on day one. Once it has been green a few times the flag comes off and it joins the required checks.

## How this will be measured

The workflow's own first run on this PR. Specifically: all four required jobs green, and the `native` job either green or clearly diagnosable. A CI slice that has not been observed running is not done — that is the whole point of adding it.

Secondary check: the gate must be able to fail. Confirmed locally for the commit regex; the suites are known to pass locally (core 16/16, Playwright 70/70, node 11+10+16).

## Out of scope for this session

- **The real artifact staleness guard.** `check-artifact.mjs` still only checks existence, so CI does not yet catch a stale committed WASM artifact. That is the `chore/artifact-staleness` slice; the workflow comments say so at the step.
- **The golden re-bless guard** (`scripts/update-goldens.sh` clean-tree check + justification) — same follow-up slice.
- **Fixing the vacuous tests.** CI running a test that asserts a tautology just automates a green light. That is the `test/assert-real-properties` slice, and it is the reason the audit sequences test integrity *before* the circuit work.
- Branch protection settings — repo config, owner action, documented in CLAUDE.md.

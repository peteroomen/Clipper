# M13.5 — the Uni-Vibe

**Date:** 2026-08-10
**Branch:** `claude/tone-assistant-roadmap-b91w0s` (house convention would be
`feat/univibe`; this session's harness pins the branch name)
**Roadmap item:** M13.5 — Uni-Vibe. Also the named future consumer of `OptoCell`
(shipped with M13.3, docs §64 / ADR 025).

## Goal

Ship the Uni-Vibe as pedal type `vibe`, slot **12**, wired end to end (core, C
ABI, worklet, web face + assistant, native engine + APVTS + PedalCard), with a
hard, measured acceptance bar separating it from the Phase 90 already in the
lineup. Extract the **lamp** as its own component, per the instruction
`OptoCell.h` carries.

## Research channel — establish this FIRST, because it sets the rules

**Probed 2026-08-10, before any code:**

- `github.com` — reachable (code search works).
- `geofex.com` (R.G. Keen, "The Technology of the Univibe" — the canonical
  article) — **EGRESS_BLOCKED**.
- `montagar.com/~patj/univibe.txt` (parts list) — **EGRESS_BLOCKED**.
- No `.asc`, `.sch` or `.schx` Uni-Vibe netlist exists on GitHub (searched
  `univibe`/`uni-vibe` by extension and free text — 0 results).

So this is **the §57 / §61 situation, not the §63 one**: search-result extracts
only, no primary source, no netlist. **Every component value in this pedal is a
documented reconstruction** and §57's rule applies verbatim — *do not re-tune any
of them toward a sound; find the schematic.*

**One fact is SOURCED** and multiple independent extracts agree on it, which is
what makes the slice viable at all: the four phase-shift stages use
**staggered** capacitors — **0.015 µF, 0.22 µF, 470 pF, 0.0047 µF** — against a
conventional phaser's four matched values. Also sourced, and reported as such:
the sources state the reason for these *particular* values is not known. We model
the **stagger**, which is the structural fact; we do not invent a rationale.

**RULE ZERO (§63.14).** Three Uni-Vibe implementations exist on GitHub
(`clevelandmusicco/HothouseExamples`, `Generous-Corp/pulp`,
`rpowell5064/guitar-amp-mod`). They are **other people's models**. Nothing in
this slice is tuned toward, compared against, or copied from any of them.

## Approach

**Deliberate tone addition** (a new voice — it can move no golden by
construction, and if one moves that is a bug in the slice, not a bless).

### The acceptance bar: notch DISTRIBUTION, not "it sounds swirly"

The roadmap frames this as "four **mismatched** stages (not the Ninety's matched
four)". **That framing is wrong and the plan corrects it up front:**
`PhaserModel` already carries a deterministic **±1.5 %** per-stage detune,
specifically so its four notches do not stack into one null. So "mismatched" is
not the distinction — the *magnitude* is:

| | corner spread |
| --- | --- |
| Ninety (`PhaserModel`) | ±1.5 % — four corners essentially coincident, summing to the signature **two** moving notches |
| Uni-Vibe | 0.22 µF vs 470 pF = **~470:1** of capacitance — four corners across roughly nine octaves |

**The bar:** on an identical stimulus, measure the frequency of each notch in the
dry+wet sum and assert the **spread** (max/min notch frequency, in octaves)
differs between the two models by a large, hard-coded margin — the §57.4-shaped
"measurably not a re-skin" test, computed against the sibling rather than quoted.
Margin to be **recorded, not snugged**.

### The lamp is a new component, and `OptoCell` must NOT be widened

`OptoCell.h` names this slice and gives the instruction in terms: *"Do not grow
this class a `lightSourceKind` axis... a lamp's drive law is a different function
of a different quantity. Extract THAT if and when it arrives."* It has arrived.
So: a new `LampDrive` component (incandescent filament — thermal mass, so
brightness lags drive **asymmetrically**, rise ≠ fall), feeding four `OptoCell`s
held **by value**. `OptoCell` gets **zero** new parameters. If it turns out it
cannot be reused unwidened, that is a finding to report (ADR 023's procedure:
build the substitution and measure it), not a licence to add an axis.

**Second bar, and it is the one a JFET phaser cannot fake:** the lamp's thermal
lag makes the sweep **asymmetric in time** — the rise and fall of the notch
frequency have measurably different slopes at the same SPEED. `PhaserModel`'s
rounded-triangle LFO is symmetric by construction. Assert the asymmetry ratio,
and assert the Ninety's is ~1.0 on the same measurement.

### Modes, and the §62 trap

The real pedal has CHORUS (dry + wet) and VIBRATO (wet only). **§62 hit exactly
this and the lesson is written down:** forwarding a mode as a hard switch clicked
at **17.02×** the signal's own slew, and the fix was to never switch — vibrato is
the same dry/wet pair with the dry weight smoothed to zero. Do that here from the
first line rather than discovering it again.

Knobs: **SPEED / INTENSITY / MODE** (slots 0/1/2).

### Oversampling — decide by measurement, do not assume

The phaser precedent (§12) is linear-time-varying → no oversampling, latency 0.
But §61.7's gate declined OS *on measurement* after a first draft shipped it, and
§64 measured that a gain-cell multiply by an audio-rate signal genuinely needs
it. The photocell divider here is a multiply by a control signal. **Measure the
non-harmonic floor at 1×/2×/4×/8× and let the number decide**; a floor flat in
the factor means it is not aliasing (§54's tell), and a windowing check comes
first (§60's trap: a rectangular window's own sidelobe read as a −55.8 dB floor).

## How this will be measured

| Property | Tool | Bar |
| --- | --- | --- |
| Notch spread vs the Ninety | new ctest, both models, identical stimulus | large contrast in octaves, margin recorded |
| Sweep asymmetry (the lamp) | new ctest | Uni-Vibe ≫ 1.0, Ninety ≈ 1.0 |
| `OptoCell` unwidened | diff | zero new params on that class |
| Alias floor vs OS factor | `--alias-report` + Hann-windowed Goertzel | decides the factor; flat-in-factor ⇒ not aliasing |
| All five goldens | `--golden-report` | **UNCHANGED at ±0.00, nothing blessed** |
| Existing suites | `ctest -N` then full run | 35 → 36 entries, all green |
| Phase 90 untouched | render hash | bit-identical |
| CPU / latency | `clipper-bench` | reported, not bounded |
